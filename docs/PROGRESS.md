### 2026-10-17 · T03 Tenant onboarding

- **Built:** `POST /auth/signup` creates the tenant (with a `pk_live_` widget key) and its owner in one transaction and signs them in. Admin/owner settings API: `GET/PATCH /tenant` (strict zod schema: name, branding, allowed domains, onboarding flag) and `POST /tenant/public-key/rotate`. Public `GET /widget/config?key=` returns only tenant name + branding, enforces the tenant's allowed domains against the `Origin` header, and is the only CORS-open route family. `GET /` now describes the API. Dashboard: signup page, 3-step onboarding wizard (company -> branding with live preview -> domains + embed snippet) that new owners are routed to, full Settings page with key rotation, install card on the overview. The widget fetches its config and applies the tenant's colour, logo, greeting and side. Seed gives Acme Bikes branding and allowed domains; four sample help articles for the demo knowledge base are in `packages/db/seed-data/acme-bikes`.
- **Files:** `apps/api/src/{tenant,widget}/*`, `apps/api/src/app.{controller,setup}.ts`, `apps/api/test/tenant.int-spec.ts`, `apps/dashboard/app/{signup,app/onboarding,app/settings}/*`, `apps/dashboard/components/tenant/*`, `apps/widget/src/*`, `packages/shared/src/tenant.ts`, `packages/db/migrations/0002_*`, `packages/db/seed-data/*`
- **Verify:** `scripts\doctor.cmd` -> all steps pass (28 integration tests: signup, duplicate email, settings, mass-assignment rejected, agents get 403, config exposes only public fields, CORS open for widget routes only, foreign origin -> 403, rotated key -> 404). Manually: `pnpm dev`, http://localhost:3000/signup -> wizard -> snippet; http://localhost:5173 shows the widget in Acme's teal.
- **Decisions:** D17-D19 in ARCHITECTURE.md. CORS is done with the `cors` middleware per route (typed, replaces Nest's single global setting). Empty allowed-domains list means "open while testing".
- **Fixes along the way:** `pnpm dev` no longer races package builds (separate `dev:packages` watcher); the doctor now smoke-tests `pnpm dev` and uses a fresh log per run; the sync to the PC refuses to delete migrations generated there.
- **Next:** T04 Knowledge base upload (PDF / text / URL).

### 2026-10-17 · T02 Auth with roles

- **Built:** `tenants`, `users`, `refresh_tokens`, `invites` tables (migration 0001, generated by drizzle-kit). `POST /auth/login`, `/auth/refresh`, `/auth/logout`, `GET /auth/me`: argon2id passwords, 15-minute access JWT kept in memory, rotating httpOnly refresh cookie with family-based reuse detection. Global `JwtAuthGuard` (routes private by default, `@Public()` opts out) and `RolesGuard` (`@Roles('admin')` = admin or owner). Team list + invites (owner invites admins/agents, admin invites agents, single-use 7-day links). Dashboard: login page, `/api` proxy so the cookie is first-party, middleware redirect, silent refresh, role-aware app shell, team + invite pages, accept-invite page. Demo seed: Acme Bikes with an owner, admin and agent.
- **Files:** `packages/db/src/schema/*`, `packages/db/migrations/0001_*`, `packages/shared/src/auth.ts`, `apps/api/src/auth/*`, `apps/api/src/users/*`, `apps/api/test/*`, `apps/dashboard/{app,components,lib}/*`, `apps/dashboard/middleware.ts`, `scripts/doctor.ps1`
- **Verify:** `scripts\doctor.cmd` -> all steps pass: 31 unit tests and 15 integration tests, including "agent gets 403 on an admin-only route", refresh rotation, replayed token revokes the session, logout, and the full invite flow. Manually: `pnpm dev`, open http://localhost:3000/login, sign in as `owner@acme.test` / `Password123!`, open Team, invite an agent, open the printed link in a private window.
- **Decisions:** D13-D16 in ARCHITECTURE.md (memory access token + rotating refresh cookie, `/api` proxy, `@node-rs/argon2`, shared zod schemas). Integration tests now migrate the test database in Jest `globalSetup`. The doctor appends new `.env` settings, generates migrations from the schema and seeds demo data. Fixed migration 0000's journal timestamp so migrations always apply in order.
- **Next:** T03 Tenant onboarding (signup, public key, branding, widget config endpoint).
