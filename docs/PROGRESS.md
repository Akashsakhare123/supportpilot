### 2026-10-21 · T13 Stripe billing and plan limits

- **Built:** plans in code (`packages/shared/src/billing.ts`): Free (100 AI answers a month, 5 documents, 1 agent), Pro ($49) and Business ($199). Owner-only API: `GET /billing` (plan, Stripe status, renewal / cancel date, payment-failed flag, usage meters), `POST /billing/checkout {plan}` (creates the tenant's Stripe customer once, returns a Checkout URL; 409 when a subscription is already live) and `POST /billing/portal` (Customer Portal). `POST /billing/webhook` verifies the Stripe signature over the raw body, skips event ids it has seen, re-reads the subscription from Stripe and applies `checkout.session.completed`, `customer.subscription.created / updated / deleted` and `invoice.payment_failed` in one transaction with the event id (new `subscriptions` and `stripe_events` tables, `tenants.stripe_customer_id`; migration 0009). Effective plan = paid plan while active / trialing / past_due, otherwise Free. **Limits:** `PlanLimitsService` + `@PlanLimit()` guard return 402 with a readable message for a 6th document (upload, URL, written answer) and an agent invite over the limit; at the monthly AI-answer limit the widget gets no AI answer: the chat goes to the team (`waiting`, reason "Monthly AI answer limit reached"), or the leave-your-email form when nobody is online, without mentioning the plan to the visitor. Dashboard **Billing** page with plan card, usage meters, plan cards (Upgrade / Manage billing) and polling after Checkout until the webhook lands. `pnpm stripe:listen` forwards Stripe CLI events to the local API.
- **Security:** plan state is only written from signature-verified webhooks, never from the client or the Checkout redirect; the client can only name `pro` / `business` (prices come from env); events find the tenant by its Stripe customer, so metadata cannot move a customer or plan to another tenant; an older subscription ending cannot cancel a newer one; replays are no-ops (all tested).
- **Files:** `packages/shared/src/billing.ts` (+ test), `packages/shared/src/{env,handoff}.ts`, `packages/db/src/schema/{billing,tenants}.ts`, `packages/db/migrations/0009_*` (generated), `apps/api/src/billing/*`, `apps/api/src/chat/chat.service.ts`, `apps/api/src/{documents,users}/*.controller.ts`, `apps/api/src/analytics/analytics.service.ts`, `apps/api/src/main.ts` (raw body), `apps/api/test/{billing.int-spec,helpers,load-test-env}.ts`, `apps/dashboard/app/app/billing/page.tsx`, `.env.example`, `package.json`, README (Stripe setup)

### 2026-10-21 · T12 Analytics dashboard

- **Built:** Analytics page (`/app/analytics`, admins and owners) and API. `GET /analytics?from&to&tz` returns KPIs (conversations, AI-resolved vs handed off, avg first response, avg agent response after a hand-off, thumbs up/down and satisfaction), one row per day, top questions and the **unanswered-questions report**; `GET /analytics/export?report=daily|questions|unanswered` downloads CSV. Date presets (7 / 30 / 90 days) and a custom range in the viewer's time zone, two Recharts bar charts with a table view, results cached in Redis for 5 minutes (Refresh skips the cache). Questions are grouped by meaning: each distinct text is embedded once and clustered (`packages/ai/src/cluster.ts`). Unanswered = low confidence, nothing found, or a thumbs down; each group shows counts, reasons, other wordings, links to the chats and an **Add doc** button that opens Knowledge base with a "Write an answer" form (`POST /documents/text`, ingested like an uploaded .md file). Widget: thumbs up / down under every AI answer (`message:feedback`, own conversation only, click again to undo); agents see the rating in the inbox, and the inbox opens a chat from `?c=<id>`. Migration 0008 adds `messages.feedback`, `conversations.first_handoff_at` (kept after "Hand back to AI", backfilled for older chats) and an index on `(tenant_id, created_at)`. `pnpm db:seed` adds about 200 deterministic demo chats over the last 30 days (`v_demo_` visitors, replaced on every seed).
- **Security:** every analytics query filters the tenant on conversations and messages, playground chats are excluded, the cache key includes the tenant id, time zones and dates are validated, CSV cells that start with `= + - @` are neutralised (formula injection), and customers can only rate AI answers in their own conversation (all tested).
